# AI 应用开发 8 周计划

> 目标不是"学完 AI"，而是 8 周后手里有 **2–3 个能演示的项目 + 一个能投简历的 GitHub**。
> 适用对象：在读工科生，会一点 C（循环/数组），每天能投入 2–3 小时。

---

## 0. 定位：先想清楚投哪类岗

| 方向 | 门槛 | 你的匹配度 | 结论 |
|---|---|---|---|
| 大模型算法 / 研究 | 硕士起步、论文/竞赛 | 低 | 不作为主线 |
| **AI 应用开发（LLM App）** | 本科可入，看项目 | 高 | **主线** |
| **智能体（Agent）开发** | 工程能力为主 | 高 | **主线** |
| AI 部署 / MLOps | Linux + 工程 | 中 | 第 6 周顺带覆盖 |
| AI 测试 / 数据标注 | 低 | — | 不作为目标 |

市场参考（2026 届校招）：大模型算法工程师月薪中位 24,760 元，但 65.8% 的企业招 AI 应届生不超过 5 人——**坑位少、门槛高**。应用类岗位不公开中位数，但更看"你能不能交付"。

**一句话战略：用项目换门票，而不是用证书换门票。**

## 3. 逐周安排

### 第 0 周：环境与工具（3 天，每天 1–2h）
- 装 Git、VS Code；注册 GitHub
- 复习 C 的**指针、结构体、文件读写**（用你 `C:\Code` 里的练习就行，不必新学）
- 建仓库 `hello-ai`，写第一个 `README.md`，完成一次 commit + push
- **交付**：GitHub 上有你的第一个仓库

### 第 1 周：Python 核心（重点周）
- 语法：变量、if/for/while、函数、参数默认值
- 容器：list / dict / set / tuple（这是 Python 的命脉）
- 字符串处理、文件读写（`open`、`with`）、异常 `try/except`
- 类与对象（够用即可，别钻设计模式）
- **交付**：命令行记账本——加一笔、删一笔、按月统计、存 JSON
- **验收**：关掉程序再打开，数据还在
- 资源关键词：B 站「彭彭 Python」「黑马 Python 基础」

### 第 2 周：工程化（决定你是"会写脚本"还是"能干活"）
- `venv` 虚拟环境 + `pip install` + `requirements.txt`
- Git 分支、`.gitignore`、commit message 规范
- 命令行参数 `argparse`、日志 `logging`、配置文件
- HTTP 基础：`requests` 发 GET/POST，看懂 JSON 响应
- **交付**：记账本拆成 `main.py / storage.py / report.py`，有 README
- **验收**：换一台机器（或新建虚拟环境）能照 README 跑起来

### 第 3 周：调用大模型 API
- 注册一个兼容 OpenAI 接口的服务（DeepSeek / 通义 / 智谱均可），拿到 API Key
- 学会：messages 结构、system prompt、temperature、流式输出
- **Key 安全**：用环境变量或 `.env`，`.gitignore` 掉，绝不提交
- 成本意识：记录 token 用量，算一次对话多少钱
- **交付**：CLI 多轮对话机器人，能保存历史会话
- **验收**：连续追问 5 轮不跑题；断网/超额有友好提示

### 第 4 周：RAG（简历上最值钱的一块）
- 概念：chunk 切分 → embedding → 向量检索 → 拼进 prompt
- 工具：`sentence-transformers` 或现成向量库（Chroma / FAISS）
- **交付**：把一份 50 页 PDF 喂进去，能回答细节问题，并给出出处页码
- **验收**：问 10 个问题，至少 7 个答对且引用准确
- 坑：切分太粗→检索不准；切分太细→丢上下文。自己调两版对比

### 第 5 周：Agent 与工具调用
- function calling / tool use 的流程：模型输出结构化调用 → 你执行 → 结果回灌
- 多步任务：拆解、循环、最大步数限制、失败重试
- **交付**：Agent 能完成"读一个本地文件，统计词频，把结果写成新文件"
- **验收**：故意给错参数，Agent 能报错并自我修正一次

### 第 6 周：Web 化 + 部署
- FastAPI 写两个接口：`/ask`、`/upload`
- 前端二选一：Streamlit（最快）或原生 HTML+JS
- Docker：写 Dockerfile，`docker run` 能跑
- Linux 基础：ssh、`systemctl`、看日志、`docker logs`
- **交付**：浏览器里能上传 PDF 并提问
- **验收**：同事/同学用手机也能打开

### 第 7 周：质量与包装（很多人跳过，最不该跳）
- 加 5 个单元测试（`pytest`），至少覆盖切分和检索
- README 必备：一句话简介、截图/GIF、如何运行、技术选型说明、已知问题
- 录 90 秒 Demo 视频：问题 → 回答 → 引用出处
- 简历一页：项目写"做了什么、怎么做的、效果如何（数字）"
- **交付**：GitHub 置顶 2 个项目 + 视频链接

### 第 8 周：投递与面试
- 投 20 家：AI 应用开发、LLM 工程师、Python 后端（AI 方向）
- 准备 3 分钟项目自述 + 10 个可能被追问的问题（为什么用向量库不用关键词？chunk 多大？怎么评估效果？）
- 八股补基础：Python 内存/并发、HTTP、数据库索引、Linux 常用命令
- **交付**：至少 5 场面试

## 6. 避坑清单

1. ❌ 先啃《深度学习》花书、先补线性代数——那是算法岗路线，投入产出比对你不划算。
2. ❌ 收藏 50 个教程但一个项目没跑通。
3. ❌ 做"教程复刻"，README 里全是别人写过的功能。
4. ❌ 把 API Key 提交到 GitHub（会被扫号盗刷，真实案例很多）。
5. ❌ 只做不写——没有 README 和 Demo，等于没做。
6. ✅ 每周日回答 5 个问题：这周交付了什么？能跑吗？卡在哪？下周砍掉什么？还剩几周？
